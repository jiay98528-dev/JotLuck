# Reink-1.0 补全引擎：运行环境与打包要求（权威档）

> 本文档是 Reink-1.0 引擎接入后的**环境与分发要求唯一事实源**。后续把它打进安装器、
> 或在别的机器部署时，先读完本文再动手，避免踩「能跑但打包后炸」的坑。
> 位置：应用侧接入代码在 `packages/app/src-tauri/src/reink_engine.rs`（Rust 宿主）与
> `reink_bridge.py`（内嵌桥接脚本）；引擎问题反馈给 Reink 训练主线会话，**不在运行包内热修**。

## 1. 运行包是什么

- 来源：`D:\VibeCoding\模型训练\06_Reink续墨补全线\release\reink-runtime-1.0\`（自包含、可整体拷贝，369MB）。
- 内容：双档权重（32M / 64M 各带 config）+ 封存分词器 + 模型代码 + 参数化生成器
  `suggestion_generator.py`（唯一入口）。
- 唯一入口契约：`generate_suggestions(prefix, lang_hint="zh", n=8, tier="32m"|"64m")`
  → `[{"text","kind":"word"|"phrase","score"}...]`（≤n 条，降序）。
- 特性：同 prefix 必同结果（逐输入定种子）；空白/乱码/回车候选零输出（垃圾闸内建，宿主不必复做）；
  超长 prefix 自动取窗口尾部（seqLen 512，约 1700–2000 字符，足够笔记场景）。

## 2. 目标机运行环境（硬要求）

| 项            | 要求                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| Python        | ≥ 3.9（推荐 3.11+）                                                                                            |
| torch         | 2.4.x 推荐（CPU 即可；CUDA 有则自动更快）                                                                      |
| sentencepiece | 0.2.x                                                                                                          |
| numpy         | 常规版本即可                                                                                                   |
| 线程环境变量  | `OMP_NUM_THREADS` / `OPENBLAS_NUM_THREADS` / `MKL_NUM_THREADS` 默认 8（包内已 setdefault，异常机器可显式设置） |

**注意：应用本体（Tauri/Rust/前端）不携带 Python 生态**。当前接入方式是宿主 spawn 系统
Python 跑桥接脚本（`reink_bridge.py`），解释器路径与运行包路径都在设置里可配
（`jotluck:reink:settings`，见 `packages/app/src/services/completion/reink-settings.ts`）。
Python / 依赖缺失时引擎 fail-closed 自动禁用并回退本地补全引擎，不影响应用其他功能。

## 4. 资源画像（决定打包与进程策略）

- 首次调用含模型加载：32M 约 1.8s、64M 约 3.2s —— 必须移到应用启动期预热（已实现：后台 warmup）。
- 常驻内存：单档约 600MB–1GB；**两档同驻约 1.5GB**（按 tier 参数惰性加载，只用一档就只驻一档）。
- 生成延迟（8 线程 CPU 实测）：32m 快速档 0.24–0.43s/次；64m 快速档 0.43–0.79s；质量档（24 采样×4 词）约慢 3 倍。
- **并发红线：模型非线程安全**——宿主必须单工作线程串行调用（Rust 侧 mpsc 队列已实现），禁止并发首调。
- ⚠️ 打包相关：`completion_decoder` 的 q4 worker 有 192MB Job 对象内存上限，**该上限对 Reink 一律不适用**
  （torch 常驻内存远超）；若未来统一 Job 限流，Reink 进程必须单列额度（建议 ≥2GB 或不限）。

## 5. 快速档 / 质量档与双档位

- 档位 `tier`：`32m`（Lite，默认——快一倍，中文主战场）/ `64m`（标准——英文显著更好 +12pp，慢约一半）。按调用传入，互不影响已加载档。
- 生成参数：质量档是包内常量 `N_CAND=24 / MAX_NEW=4`；快速档 = 宿主侧设
  `suggestion_generator.N_CAND=8 / .MAX_NEW=3`（模块属性调用时读取，**从包外赋值，不改包内文件**）。
  应用设置里的「响应优先/质量优先」即映射这两个参数组合。

## 6. 红线（训练线交接约定）

1. 权重 / 分词器 / config **只读**；升级 = 整包替换 + 重新校验第 3 节指纹，不做就地热修。
2. 引擎 bug 反馈到 Reink 训练主线会话处理，不在运行包内改模型侧文件。
3. 已知边界：不支持代码补全场景（训练无代码语料）；超长文档自动取窗口尾部。
4. 版本锚点：Reink-1.0。

## 7. 后续打进安装器的选项与阻塞点（打包立项时先读）

| 议题           | 选项                                                                                                                                             | 阻塞点                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 369MB 资产分发 | a) `tauri.conf.json` bundle.resources 直捆；b) 首启下载器 + 第 3 节指纹校验                                                                      | a) 安装包体积暴涨 ~369MB；b) 需要托管源与断点续传；两者都要动 tauri.conf.json（当前版本发布链路冻结，本期明确不做） |

| 内存限流       | 见第 4 节                                                                                                                                        | 任何统一 Job 限流改动必须豁免 Reink 进程                                                                            |

## 8. 本期边界（截至 2026-10-14）

- 仅本机/开发环境接入：默认运行包路径即第 1 节路径，设置可改；不随安装器分发、不动打包配置。
- 应用内开关/档位/模式/路径设置：设置 → 自动补全 → Reink 区块（`jotluck:reink:settings`）。
- 引擎不可用（无 Python / 无运行包 / 超时）→ 自动禁用并回退既有本地补全引擎，无用户可见报错风暴。
