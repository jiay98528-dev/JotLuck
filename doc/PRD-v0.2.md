## 1. 背景与动机

JotLuck 已是本地优先、离线可用的 Markdown 笔记（当前 `v0.14.0-preview`），具备：三态视图（即时预览/分栏/阅读）、CodeMirror 6 混合渲染即时预览、离线 AI 补全（V2.5 个性化已上线）、Office/PDF/Excel 只读导入、6 格式导出。

三个推动转型的事实（2026-09-13 只读探查核实）：

1. **编辑体验已到七成，欠账明确**：即时预览已做非聚焦块渲染、Markdown 定界符零宽折叠（`packages/app/src/utils/cm6-live-preview.ts:140` `SOURCE_MARK_NODE_NAMES`、`:814` `RenderedBlockWidget`、`:1430` `buildSourcePreservingDecorations`）；但列表/表格换行不延续格式、聚焦块回退纯源码破面、查找替换装了没接线（`@codemirror/search` 零引用）。
2. **语法解析正在屎山化**：同一套 Markdown 语法在 **7 处独立解析**——渲染库（marked 仅扩展 wiki-link + tag，`packages/renderer/src/marked-extensions.ts:54,90`）、`services/YAMLParser.ts:17`、`services/IndexService.ts:265-283`、`composables/useHeadings.ts:23`、`utils/blockParser.ts:6`、`utils/markdown-formatting.ts:11`、`components/modals/ShareDialog.vue:280`，Rust 端 `src-tauri/src/indexer.rs:389-410` 再一份标题/标签提取。每加一种语法要改 7 个地方，漏一处就是一个 BUG。
3. **导出是三条独立路线**（`services/Exporter.ts`，1098 行）：DOCX 用 marked lexer 自写构建、XLSX/CSV 用字符串判定抽表格、TXT 用 14 条正则手工剥离——均未走统一文档模型。

owner 定调（2026-09-13）：**深入打磨输入体验；深化渲染模型；把独立并行的渲染代码打通、合并成统一的一套语法，避免不可维护的屎山化**。弱化 Markdown 的「用户可见定位」，渐进转型为类 Word 的强化文本&笔记编辑软件，打通各格式的转译、渲染与导出壁垒。

**对标产品**（owner 2026-09-13 确认）：**Word**（编辑手感目标）与 **Obsidian**（混合渲染与本地优先的同构参照——Obsidian 本身即 CodeMirror 6 + Live Preview 路线，印证本代际「不换内核、深化混合渲染」的技术路径）。注：此前语音输入中的 "substandard" 系 Obsidian 误识别。

## 2. 定位变化：什么变、什么不变

**变**：

- **用户可见层去语法化**：用户不必认识 Markdown 即可完成全部排版；语法符号退居幽灵/弱化呈现（R2）。
- **编辑手感对标 Word 级**：结构化的格式预测与预填（R1），渐进逼近，不换编辑器内核先行。
- **格式能力升级**：从「Markdown 渲染 + 6 条独立导出」升级为「统一文档模型（AST）驱动的多格式转译中枢」（R3）。

**不变（红线，违反即业务阻塞）**：

- 存储仍是纯文本文件（`.md/.markdown/.mdx/.txt`），文件夹即笔记本；任何文本编辑器可打开；**不引入任何数据库**。
- 本地优先、离线可用；DOMPurify 双清洗、授权目录、原子写入、trusted-code 确认等安全边界不变。
- **诚实到字节**：R2 的幽灵化只改显示层，文件字节永远不变；「转换不冒充原件」继续有效——不承诺像素级 Office 复刻、不原位编辑原件（NG-006 维持）。
- AI 补全交互模型不变（单条 ghost、Tab 接受、Escape 拒绝）；新功能的键位与 ghost 的冲突按 §6 仲裁。
- **自研新纯文本语法：不立项**。存储保持 Markdown 超集；表达力缺口按「扩 Markdown 超集（callout/脚注/数学，渲染库注释中已规划）→ 评估 Djot/AsciiDoc → 自研（永远最后）」的顺序处理。理由（2026-09-13 分析，owner 已阅）：「看不见语法」由渲染层解决、不需要新语法；Markdown 是 AI 时代通用语，自研语法自绝生态；换语法将连带重写 7 处解析、索引、导出与补全结构化平面，V2.5 模型本身即在 Markdown 语料上训练。

## 3. 目标与非目标

**目标（V0.2 代际）**：

- G1 输入体验：格式预测与预填——列表/表格/引用/任务等结构在 Enter 时自动延续，Backspace/ESC 立即取消预填（R1）。
- G2 渲染模型：聚焦行保持渲染不中断，格式符号幽灵化弱化可见——在「聚焦显源码」与「全渲染隐符号」之间取居中点（R2）。
- G3 一套语法：统一解析实现为单一权威，消灭 7 处并行解析；渲染、导出、索引、编辑全部消费同一来源（R3）。
- G4 体验补完：查找替换、斜杠命令、表格编辑、大文档与触摸等欠账按优先级滚动交付（R4）。

**非目标（本代际不做）**：

- 不换编辑器内核（CodeMirror 6 保留）。ProseMirror/TipTap 级富文本内核仅在 G2 天花板被真实需求撞破后另立风险评估，不在本计划内。
- 不做双向无损 docx 编辑、不做像素级 Office/PDF 复刻、不 OCR（维持 NG-006）。
- 不发明新存储语法；不引入数据库、云同步、账号。
- KEY_OBJECTIVES 正式 reposition 与 PRODUCT.md 定位段改写另立流程，不在本文档执行。

## 4. 核心需求详述

### R1 智能续格式（格式预测与预填）

**用户故事**（owner 原话收敛）：

- 用户正在编辑有序或无序列表，按下回车 → **直接新建下一列表项**（延续编号/符号），而不是新起一行普通段落。
- 用户正在编辑表格，按下回车 → **直接新建下一行表格**。
- 预填的格式块出现后，用户不想继续时，按 **Backspace 或 ESC 立刻取消预填的格式块**（回到普通段落）。
- 推广：根据用户前面的输入**预测后面的格式并预填**——引用块、任务列表同理延续；更宽的模式预测（如连续重复前缀）进入 R4 候选池，可复用补全引擎的结构化平面。

**行为细则（初稿，切片 A 开发时冻结为规格）**：

- Enter 延续：光标在结构块行尾 → 延续同构新块；光标在块中 → 拆分并延续格式（Word 惯例）。引用块、任务列表（延续为未勾选项）同规则。（2026-09-13 实现补记：表格延续以「相邻管道行组内存在分隔行」为前提——GFM 语义下无分隔行的孤立管道行只是普通段落；这保证手工逐行构建表格时表头/分隔行阶段的回车仍是普通换行，分隔行建立后数据行回车才开始预填新行。）
- 取消语义：预填产出的是**空格式块**（如 `- `、空表格行）。在空格式块上：Backspace → 移除预填、转为普通段落；ESC → 同效（与 ghost text 的优先级见 §6）；**Enter → 同样退出结构**（删标记、起普通新行——owner 2026-09-13 拍板，与 Word/Obsidian/Typora 手感一致）。
- 原子性：每次预填/取消是一次可整体撤销的编辑。
- IME 红线：中文输入法组合（composition）期间不得触发任何预填或取消（错题本 BUG-016/032/036/038/048/052/060 全部为 IME 坑，切片 A 必须逐条复查）。
- 全角归一：`＃ ＊ ＞ － ［` 等全角符号在结构识别时归一处理（顺带修复 BUG-055）。

### R2 聚焦行幽灵语法（渲染不中断的居中点）

**现状**：即时预览中光标所在块回退为纯源码显示（`cm6-live-preview.ts:1355-1377` 焦点切换），渲染「破面」。

**目标（owner 原话收敛）**：即时渲染模式下，即使用户聚焦当前行，也**不打断即时渲染效果**；该行的源码格式符号（`**`、`#`、`[]()`、表格管线符等）以**幽灵字符或某种高亮形式**弱化显示。即在「聚焦行显示源码不渲染」与「聚焦行全部渲染不显示任何符号」之间取一个**居中点：渲染保持 + 符号幽灵化**。

**行为细则（初稿，切片 C 冻结）**：

- 聚焦块的行内格式保持渲染（加粗仍是粗体、标题仍是大字）；该块的格式符号以低对比度/缩小/着色的幽灵形式原位显示，光标可精确落在符号前/后。
- 链接：光标进入链接文字时，URL 以幽灵形式尾随显示并可编辑（不弹窗）。
- 选区映射：在渲染文本上点击/拖选，光标与选区必须落到正确的源码偏移——这是本需求最高风险点。
- IME 红线：组合期间冻结装饰重建（沿用 BUG-048 修复纪律），组合结束后一次性映射。
- 设置项（P2 可选）：提供「聚焦显源码（现状）/ 居中点（默认）/ 全渲染隐符号」三档；首版只做默认居中点。

**技术前提（已核实的钩子）**：`SOURCE_MARK_NODE_NAMES`（`cm6-live-preview.ts:140`）已把 `HeaderMark/EmphasisMark/CodeMark/LinkMark/URL/LinkLabel` 折叠为零宽；居中点 = 把「零宽折叠」改为「幽灵内联显示」，并解决坐标映射。**先在「单个行内块的符号幽灵化」上做风险原型，验证坐标/IME/选区三件事后再放量**——kill/keep 判据：中文 IME 连续输入 200 字无坐标漂移；渲染文本任意位置点击光标落点正确率 100%。

### R3 一套语法：统一解析与渲染管线（反屎山）

**目标（owner 原话收敛）**：把之前独立并行开发的渲染代码全部打通，**合并成统一的一套语法**（一套解析实现、一处权威、多处消费），避免不可维护的屎山化。

**需求**：

- 建立唯一权威解析器，产出统一文档模型（AST/块模型），覆盖：frontmatter、标题、段落、列表（有序/无序/任务）、表格、代码块、引用、行内格式、wiki-link、tag、图片、链接。全角归一在这一层一次性做。
- **7 处并行解析全部迁移收口**（已核实清单）：

| 现有解析点                | 位置                                                                                   | 迁移后                       |
| ------------------------- | -------------------------------------------------------------------------------------- | ---------------------------- |
| 渲染扩展（wiki-link/tag） | `packages/renderer/src/marked-extensions.ts:53-111`                                    | 权威解析器所在处             |
| frontmatter               | `services/YAMLParser.ts:17`、`services/IndexService.ts:265`、`services/Exporter.ts:69` | 统一 AST 的 frontmatter 节点 |
| 标题提取（大纲）          | `composables/useHeadings.ts:23-27`                                                     | 消费 AST                     |
| 标签/wiki-link（索引）    | `services/IndexService.ts:266-283`                                                     | 消费 AST                     |
| 块识别（编辑器）          | `utils/blockParser.ts:6-15`、live preview 块解析                                       | 消费 AST                     |

- **Rust 索引收口**：首选——前端统一解析器产出结构化字段（title/tags/links）随索引提交，Rust 只存储不解析；备选——Rust 端口同一规则集。切片 B 启动时以「规则单一来源」裁决，**不允许第三份解析长期并存**。
- **导出收口**：DOCX/XLSX/CSV/TXT 全部改为从 AST 产出（废除 `Exporter.ts` 的字符串剥离与独立表格抽取）。收口后新增一种格式只需写「AST ↔ 格式」两个适配器。
- **语法扩展单点化**：callout、脚注、数学在统一 AST 上一次实现、处处生效。
- **技术选型纪律**：marked 是否继续作为 AST 底层（复用其 lexer）或替换为自维护解析器，属切片 B 的普通技术选择，由执行者按「一份实现、全部消费、行为等价」标准自行裁决并登记 ADR；选型锁定表随 ADR 更新。
