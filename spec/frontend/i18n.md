# Frontend Internationalization

版本：2026-08-04

## 支持范围

- 支持语言：`zh-CN`、`en`、`ja`、`ko`、`fr`。
- 主目录与最终回退：`zh-CN`。
- 应用拥有的 UI、ARIA、程序错误、官方主题、内置模板/示例、导出包装和原生安装体验必须本地化。
- 用户笔记、自定义模板、既有示例、第三方主题作者文本、Markdown/文件格式标识及补全引擎内部内容不翻译。

## 启动与持久化

1. 读取 `jotluck:locale:v1`，合法值优先。
2. 无合法值时按 `navigator.languages` 逐项尝试精确 BCP-47 与主语言匹配；`zh-*` 归一化为 `zh-CN`。
3. 无匹配时使用 `zh-CN`，并把结果写回持久化键。
4. 目标消息目录加载完成后再挂载 Vue；加载失败只回退中文。
5. 用户切换立即更新消息、`html.lang/dir/data-locale` 与其他同源窗口，不刷新页面。

## 消息与格式化

- `zh-CN` 对象定义 MessageSchema；五份目录的 key、复数分支和插值参数必须一致。
- key 使用稳定语义路径，不使用源文案。完整句子作为单条消息，不依赖拼接语序。
- Vue 组件使用 Composition API；服务、配置工厂和 CodeMirror 扩展使用 LocaleManager 的显式翻译/格式化函数。
- 日期、数字、相对时间和自然排序由当前 locale 的 Intl formatter/collator 生成；文件路径、Markdown 和用户内容不得被 locale 转换。
- 模板占位符名称和稳定机器格式不变；`weekday`、`week` 仅本地化自然语言部分。

## 错误合同

- 可能进入本地化 UI 的文件系统、索引、原生对话框等 IPC 与对应 MockFS 路径使用同一 `CommandErrorPayload { code, args? }`。补全检索与仅供内部诊断的接口不属于该合同，其错误不得直接进入 UI。
- 支持码：`not_found`、`permission_denied`、`already_exists`、`invalid_path`、`outside_notebook`、`not_utf8`、`file_too_large`、`conflict`、`disk_full`、`notebook_not_open`、`index_unavailable`、`operation_failed`。
- 前端预期错误使用 `UserMessageError { key, args?, diagnostic? }`；普通 `Error` 只能触发当前上下文的本地化兜底消息。
- UI 只能展示消息目录解析结果；底层诊断字符串仅可进入诊断字段、日志或非展示回调，不得作为翻译插值或页面文案。

## 扩展与验证

- 新语言必须同时加入注册表、完整消息目录、本地化内置内容、字体降级、NSIS 资源和 locale matrix 测试。
- `i18n:check` 拒绝目录不一致、插值不一致，以及 Vue 模板/已知用户消息 API 中新增的未结构化文案。
- 五语言组件矩阵覆盖长文案、键盘、360px、200% 缩放；E2E 验证切换、刷新持久化与笔记内容不变。
