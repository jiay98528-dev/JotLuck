| 字段       | 说明                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 上下文锚点 | 一句话说清工程与相关文件路径（模型零上下文起步）                                                                                               |
| 窄目标     | 单产物、单动作；一次会话只做一件事                                                                                                             |
| 可改范围   | 精确到目录/文件名（默认仅 `scratch/<任务名>/`），**产物路径写绝对路径**（P5 实测相对路径会被解析到仓根而非 site/）                             |

## M1 格式化产物 + 精确编辑 —— 评级：✅ 可派

- 用途：严格 schema 的 JSON/配置、清单文件；单文件单行级 Edit。
- 要点：schema 逐字给出（键序、缩进、尾随换行等字节级要求显式写明——P1 实测尾随换行会被漏）。
- 验收：主线程 node 脚本比对 schema/键序/字节内容。

## M2 窄翻译 —— 评级：✅ 可派（≤5 短句/批）

- 用途：短 UI 文案 zh→ja/ko/fr（复用会话 #1，保留其 i18n 上下文）。
- 要点：产品语境与语气一句话说清；输出严格 `{lang: {key: 译文}}`；禁残留规则写明（ko/fr 不得含汉字，ja 汉字豁免）。
- 验收：键对称 + 残留正则机器查；语气人工抽查。

## M3 只读分析 + 结构化 JSON —— 评级：⚠️ 可派（须规定口径，结论复核）

- 用途：计数、清单、事实提取（复用会话 #2）。
- 要点：**计数口径逐字定义**（例：「字符串 X 的出现次数，含闭合标签，按 occurrence 不按行」——P3 实测会默认行数口径）；禁止猜测写明。
- 验收：主线程预先独立取得真值，逐字段对照。

## M4 小函数实现 —— 评级：⚠️ 可派（规格须附边界向量表）

- 用途：≤60 行纯函数/小模块（复用会话 #3）。
- 要点：规则编号逐步给出；**必附边界用例**（Unicode 扩展、全角、空串、重复折叠——P4 实测规格边界会向 ASCII 收缩）；要求 CLI 自测仅供调试，不作验收依据。
- 验收：主线程 harness 跑全向量（含规格边界），不看自报输出。

## M5 视觉读图 QA —— 评级：⚠️ 条件可派（v2 修订）

- 依据：P5/P5R 判禁用后，V 轮复验（能力报告 §6）翻案——宏观布局、干净底文字 OCR（含 0.75rem 细字）、双图比较、诚实出口全部通过。
- 可派：宏观布局/计数判断；**干净背景**上的文字 OCR；双图比较。输入须为主线程预制的**原尺寸裁剪图**（禁直接喂全页长图问细字）。
- 禁派：**纹理/图案底文字、反白/低对比文字**（必幻觉且不报错）；任何缺诚实出口（unreadable 分支）与真值对照的读图任务。
- 工程前提：产物绝对路径 + unreadable 出口条款 + 主线程真值对照。

## M6 脚本编写（主线程跑） —— 评级：❌ 暂不上放 M3

- 依据：verify-dist.mjs（200+ 行断言脚本，deepseek 一次写对）超出 M3 当前可信区间。需要新验证脚本时：主线程手写，或回退 deepseek 会话（注册表模型约束段）。
